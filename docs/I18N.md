# Internationalization & Accessibility (I18N) Guide

## Overview

Stellar Nebula supports internationalization and screen reader accessibility through standardized language attributes, client-side language preference detection, and dynamic switching.

## HTML `lang` Attribute

The HTML root element (`index.html`) includes the mandatory `lang="en"` attribute by default:

```html
<!doctype html>
<html lang="en">
  <head>
    ...
  </head>
</html>
```

### Screen Reader Support

Setting the `lang` attribute on `<html>` is critical for assistive technology:

- **Pronunciation**: Screen readers (VoiceOver, NVDA, JAWS) use `lang` to determine pronunciation rules, accent, and speech synthesis.
- **Hyphenation and Punctuation**: Browsers correctly format quotes, punctuation, and hyphenation according to locale rules.
- **WCAG Compliance**: Satisfies WCAG 2.1 Success Criterion 3.1.1 (Language of Page) and 3.1.2 (Language of Parts).

## Dynamic Language Switching with `useLanguage`

The application provides the `useLanguage` hook (`src/hooks/useLanguage.ts`) for managing active language state and syncing with DOM attributes.

### Hook Features:

1. **Detection**: Automatically detects preferred language from `localStorage` (`stellar_nebula_lang`) or browser settings (`navigator.language`).
2. **Dynamic HTML Updates**: When language switches, `document.documentElement.lang` and `dir` are dynamically updated.
3. **Persistence**: Saves language choice across user sessions in `localStorage`.
4. **Supported Locales**:
   - `en` - English (Default, LTR)
   - `es` - Español (LTR)
   - `fr` - Français (LTR)
   - `de` - Deutsch (LTR)
   - `ja` - 日本語 (LTR)
   - `zh` - 中文 (LTR)

### Example Usage:

```tsx
import { useLanguage } from '@/hooks/useLanguage'

export function LanguageSelector() {
  const { language, setLanguage, supportedLanguages } = useLanguage()

  return (
    <select
      value={language}
      onChange={(e) => setLanguage(e.target.value as any)}
      aria-label="Select application language"
    >
      {supportedLanguages.map((lang) => (
        <option key={lang.code} value={lang.code}>
          {lang.name}
        </option>
      ))}
    </select>
  )
}
```

## Testing I18N

Unit tests in `src/hooks/__tests__/useLanguage.test.ts` verify:

- Initial HTML lang attribute presence and defaults
- LocalStorage language persistence
- Document `lang` attribute updates upon language change
- Directionality (`dir="ltr"` / `dir="rtl"`) handling
- Fallback to English for unsupported locale codes
