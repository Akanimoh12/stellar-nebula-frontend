# PWA and Caching

The service worker is generated by `vite-plugin-pwa` (Workbox `generateSW`) from the `VitePWA` block in `vite.config.ts`.

## Caching strategies

| Resource                                     | Strategy                           | Cache                |
| -------------------------------------------- | ---------------------------------- | -------------------- |
| Build output (`/assets/*`, hashed filenames) | Precache + `CacheFirst`, no expiry | `build-assets-cache` |
| Images                                       | `CacheFirst`, 30 days              | `images-cache`       |
| Local fonts                                  | `CacheFirst`, 1 year               | `fonts-cache`        |
| Stellar APIs (`*.stellar.org`)               | `NetworkFirst`, 10s timeout, 5 min | `stellar-api-cache`  |
| Google Fonts (`googleapis`, `gstatic`)       | `CacheFirst`, 1 year               | `google-fonts-cache` |
| Other HTTPS resources                        | `StaleWhileRevalidate`             | `external-cache`     |

Navigations fall back to the precached `/index.html` when offline (`navigateFallback`). In addition, a standalone offline fallback page is maintained at `public/offline.html` and available at the `/offline` route with cached vessel diagnostics, cached asset registry inspection, and interactive reconnection probing (#324).

## Versioning and updates

- Caches are prefixed with `cacheId: 'stellar-nebula'` and outdated precaches are removed (`cleanupOutdatedCaches`).
- `registerType: 'prompt'` keeps the new worker waiting; `useServiceWorkerUpdate` shows the update toast and activates it on request (or after the user has been idle).

## Rendering and assets

- `src/styles/critical.css` is inlined into `index.html` by the `inline-critical-css` plugin, so the first paint does not wait for the bundled stylesheet. Keep it to above-the-fold basics.
- The app uses system fonts, so there are no font files to preload.
- `OptimizedImage` lazy-loads images and accepts `webpSrc` to serve WebP with `src` as the fallback.
- `npm run images:check` fails if any image in `public/` or `src/assets/` exceeds 100 KB.

## Dead code

- `package.json` declares `sideEffects` as CSS only and the build uses Rollup's `recommended` tree-shaking preset, so unused modules are dropped. A module that must run for its side effects when imported needs an entry in `sideEffects`.
- `npm run unused-exports:check` (run in CI) fails on exports under `src/` that production code does not import, except those in `.unused-exports-baseline.json`. After removing an export, run `npm run unused-exports:update-baseline` to prune it.
